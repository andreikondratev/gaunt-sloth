# v2.0.0-beta.14

- A review that fails inside the agent exits non-zero, and the review report is written even when
  the run fails before the agent starts. A broken review used to leave a green CI job and nothing
  to explain it. See Potentially Breaking Changes below.
- The plain readline session (`--no-tui`) serves session history, and shows the load-time
  configuration warnings that until now only the full-screen TUI showed. Where history genuinely is
  not available there, the reason given is the real one — the fallback used to name a configuration
  setting that was never the problem.
- An ACP client can list the refusals a session saved and take one back. The editor draws the
  command itself, through the protocol's own available-commands update rather than a custom
  extension, on both dialects. Alongside it: a cancelled or unreadable answer is no longer archived
  as though you had refused, a session ending with a prompt still on screen says it is tearing down
  rather than that you refused, and the resume banner names the stored path as the project root it
  is.
- `/clear` drops the approvals capture log along with the thread, so what the command said it
  cleared is gone.
- The launch banner reports the working directory the session is actually running in, with the
  configuration root beside it.
- `/status` tells a user whose `autocompact` threshold is a share of the context window, and whose
  window no source could resolve, that the setting is accepted and does nothing — and names the
  absolute form (`/autocompact 300K`, or the `autocompact` config key) that would fire instead.
- One Esc press leaves a maximised debug pane, giving the rows and the keyboard back together, and
  the pane's key legend names which mode the keyboard is in. The progress indicator and the notice
  about reading piped STDIN now honour the console level.

## Potentially Breaking Changes

- A review that fails inside the agent now exits 1. This is deliberately not gated on
  `errorOnReviewFail`: that key governs what to do with a verdict, and a run that never reached a
  verdict has no score to act on. A CI job that was passing because a broken review exited 0 will
  now fail, which is the point.
- Three caps exported from `@gaunt-sloth/core` are renamed to say what they budget:
  `TOOL_PREVIEW_LINE_MAX_CHARS`, `TOOL_PARAM_VALUE_MAX_CHARS` and `TOOL_SUMMARY_MAX_CHARS` become
  `TOOL_PREVIEW_LINE_MAX_COLUMNS`, `TOOL_PARAM_VALUE_MAX_COLUMNS` and `TOOL_SUMMARY_MAX_COLUMNS`.
  Values and behaviour are unchanged, and the old names are gone with no alias. This reaches
  embedders importing them; the CLI is unaffected.
