# v2.0.0-beta.10

- Guidelines can now be chosen by the files a change touches. `prompts.paths` takes an ordered list
  of path-scoped overlays, selected from the diff under review before the model is called, so a
  monorepo review no longer gets one guidelines file for the whole repository.
- At `auto`, a command the rater never actually assessed goes to you instead of back to the agent. A
  gate that failed to obtain a rating used to open a negotiation, which made the strictest rater
  available produce the most permissive outcome by failing to answer at all. A rater that did answer
  is unchanged, however oddly it worded itself.
- A module config's `configure()` can return a model it built itself. That is the shape the
  documentation describes, and the global-only path was refusing it by name because it carried no
  `type` key.
- `consoleLevel: "display"` now leaves one line per tool call — the row naming the tool and its
  arguments — instead of nothing at all. The `Requested tools:` and `Thinking...` lines are what fall
  silent. Pair it with `toolOutputPreviewLines: 0` for exactly one line per call.
- Two medium `qs` advisories are closed in the AG-UI server's runtime tree.
- Every third-party patch and minor bump is taken, the LangChain 1.x line included. One behaviour
  follows from it: a bare string sitting in an assistant message's content array no longer counts
  towards the answer text, which is what `@langchain/core` itself stopped doing in 1.2.10.
- `@gaunt-sloth/core` now declares its optional provider peers at the versions the CLI ships. The
  floors had drifted low enough that a bump moved the CLI and left the library behind, so the two
  were resolving different copies of the same provider.

## Potentially Breaking Changes

- **The rater no longer suggests a granted alternative to the command it refused.** Steering the
  model off the shell and onto a built-in was not a contest the gate won, and the granted list was
  the one place locally-authored tool text sat outside the rater prompt's fenced untrusted block. A
  refusal now says only that it refused. Nothing to change in your configuration; expect a refused
  command to be retried differently, or not at all, rather than redirected. The rung-aware tool
  descriptions are untouched.
